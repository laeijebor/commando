Browser tiles among tmux panes

Let agents (and you) open a web page as a first-class tile inside the pane grid — a Lavish review page, a dev server, docs — sitting right next to the tmux pane where the agent is working. The agent publishes something, calls one endpoint, and the page appears beside its pane in every connected Commando client. Everything below is verified against the codebase; the two hard constraints (CSP, tmux layout validation) are called out where they bite.

What it looks like

Commando's real tokens and pane chrome (.terminal-pane / .pane-head / .pane-footer, src/styles.css:1195-1230). A browser tile is the same card shell as a terminal pane — same header, same splitters, same focus ring — with a URL pill where the title sits and a page instead of a terminal.

The core loop this enables. The agent serves a page (Lavish, npx serve, a vite dev server…), runs commando open <url> from its own tmux pane, and the tile appears beside that pane — the daemon knows which pane the agent lives in from $TMUX_PANE. The two tmux panes are still real tmux panes; the tile takes its share of screen space and Commando's existing measured-layout path resizes the real panes around it. The toast attributes who opened it; ✕ closes, ⤴ opens in the OS browser, ↻ reloads.

The crux: where a browser tile lives in the layout

Everything on the canvas today mirrors tmux: the daemon polls window_layout, the client parses it into a tree (shared/window-layout.ts:31), and ResizablePaneLayout renders one React node per leaf (src/ResizablePaneLayout.tsx:197 — it's just panes.get(node.paneId), so any React node can already be slotted for a leaf). But a browser tile is not a tmux pane, and the daemon rejects layout writes whose pane set differs from the window's real panes (server/index.ts:1275-1290). Two ways out:

Recommended

App-layer leaf

The tile exists only in Commando's rendered tree: a new web leaf kind in WindowLayoutNode, inserted beside its anchor pane, and stripped before any tmux write (layoutSpecFromTree, applyMeasuredWindowLayout, commitWindowLayout).

  • tmux stays clean — attach from a raw terminal and you see only real panes.
  • Resize already works: when this client holds the resize lease, the measured-layout path shrinks the real panes to the space the tile leaves them, exactly like the HUD does today.
  • Persists in SavedGroup (shared/protocol.ts:233) → survives reload, follows the group.

cost: client tree surgery + strip-before-write discipline

Not recommended

Placeholder tmux pane

Create a real tmux pane running a stub process to reserve geometry, and render the web view over its slot.

  • Pollutes tmux — every attached terminal sees a junk blank pane; killing it from raw tmux desyncs the tile.
  • Costs a pane slot against MAX_LAYOUT_SPEC_PANES and confuses the resize-lease baseline capture/restore.
  • Only upside: geometry is authoritative in tmux even when no Commando client holds the lease.

cost: daemon pane lifecycle + tmux noise forever

Known interaction with the resize lease. When no client holds the window's resize lease (e.g. you're viewing from a second browser), tmux keeps its own layout and Commando letterboxes panes — same behaviour as today. A web tile in that state simply renders in the app-layer tree while terminals letterbox; nothing new breaks, but the tile's neighbours won't reflow tmux until a lease holder shows up. This is the same trade the HUD/tabs already make.

Rendering tiers — both ship in v1 (your call: one effort, not two branches)

v1 · web clients

Sandboxed iframe

An <iframe sandbox> inside WebPaneCard. Requires one CSP change: the daemon sends no frame-src today, so default-src 'self' blocks all embeds (server/index.ts:75-86). Add frame-src http://localhost:* http://127.0.0.1:* https:.

  • Covers the core loop: Lavish pages, npx-serve, vite/storybook dev servers — local express servers don't send X-Frame-Options.
  • Works in every client (browser, Safari wrapper) with zero native work.
  • Sites that forbid framing get the honest fallback card + "open in browser".

cost: small — one CSP line + one component

v1 · desktop app

Native WKWebView sibling

The desktop shell already composites native terminal views above its WKWebView, driven by a rect/occlusion protocol (src/nativeTerminalBridge.ts:36-54, NativeTerminalPane). A second native view kind — commando.native-webview — reuses that exact plumbing to host a real browser view in the tile's rect.

  • No framing limits — GitHub, docs sites, anything renders in the desktop app.
  • Real cookies/devtools-grade fidelity; OS-level page isolation.
  • Desktop-only; browser clients fall back to the iframe tier.

cost: medium — Swift + bridge protocol rev

Skip

Daemon reverse proxy

Proxy external sites through the daemon, stripping X-Frame-Options so they frame anyway.

  • Fragile (asset paths, auth, redirects), a same-origin security headache, and deliberately defeats sites' embedding policy.
  • The native tier solves the same problem properly.

cost: high, permanent maintenance

The agent surface — first agent→UI command

There is no agent-facing control API today; agents only report status via hook endpoints (POST /api/agent-status/hooks/*) authorized by ~/.commando/agent-hook-token. This feature adds the first agent→UI command, reusing that exact auth shape — plus a tiny CLI shim so agents (and your muscle memory) don't need curl:

# what `commando open` does under the hood — callable from any agent's Bash
curl -s -X POST http://127.0.0.1:4310/api/web-panes \
  -H "Authorization: Bearer $(cat ~/.commando/agent-hook-token)" \
  -d '{ "url": "http://127.0.0.1:41300/streaks-plan",
       "anchor": "'"$TMUX_PANE"'", "placement": "right" }'

# → { "ok": true, "webPaneId": "w1", "beside": "%12" }
# close it again: DELETE /api/web-panes/w1

The daemon resolves $TMUX_PANE to the window/group and places the tile beside it (placement: right | below | auto). A pane id the daemon doesn't know → 404, mirroring pane-management-api conventions. A one-page skill/CLAUDE.md snippet teaches agents when to use it ("after publishing anything reviewable on localhost, open it beside your pane").

Risks & edge cases

RiskHandling
Iframe swallows keyboard — ⌘K and pane shortcuts die while the page has focusSame problem terminals already solve: the tile takes focus only on explicit click; a focused tile shows the accent ring; Esc (captured on the card, not the page) returns focus to the workspace. Keep a thin always-Commando border so there's always a click target.
Agent opens something unwanted / spammyURL policy (decision 4): localhost instant, external origins confirm-once; attribution toast + footer always names the opener; rate-limit the endpoint like other client messages.
Second client / no resize leaseTile renders app-side regardless; tmux reflow waits for a lease holder — identical to today's letterbox behaviour, documented in the lease callout above.
Desktop shell compositingv1 iframe is DOM inside the WKWebView, so it never fights native terminal views (tiles don't overlap). Tile context menus/toasts get data-native-terminal-occluder like every other overlay.
Dead pages (server stopped)iframe error → fallback card with reload + close; a closed Lavish session just 404s visibly instead of wedging the tile.
Persistence drift (anchor pane dies)Reconciler re-anchors the tile to the group; if the group empties, the tile closes with a toast — never an orphan leaf that blocks layout writes.

Build plan

  1. Protocol + daemon. WebPane types, registry, URL policy (localhost auto / per-origin allowlist), /api/web-panes (cookie + hook-token auth), broadcast messages, SavedWorkspace persistence, CSP frame-src. Unit tests for policy, auth, persistence round-trip.
  2. Client tile (iframe tier). web leaf in the layout tree + strip-before-write in all three tmux write paths, WebPaneCard with all states, focus/keyboard handling, reconciler survival, ⌘K command. Tests beside the existing App/layout tests.
  3. Agent surface. commando open shim + agent docs snippet, Ports-panel action, attribution toast, rate limiting.
  4. Native tier (desktop app). Bridge protocol rev to a commando.native-webview view kind; Swift NativeWebViewHost (WKWebView per tile rect, occluder masking reused from native terminals); ExternalURLPolicy update; desktop shell falls back to iframe when the capability is absent.
  5. Merge gate. typecheck + vitest, then drive the real loop end-to-end in both clients — an agent in a pane publishes a Lavish page and opens it beside itself in the browser, and GitHub renders in a desktop-app tile.

Later candidates, out of scope: pane context-menu entry, tile history/back-forward, multiple tabs per tile, screenshots of tiles for agents to read back.
