Grouped by what it costs. "Free" fields extend the existing single GraphQL fragment — no extra request. Actions marked daemon need a new daemon endpoint.

Decided: description excerpt, branch → base, ages + commit/file counts, per-reviewer status, full checks list, and unresolved thread excerpts. Labels are out. Thread comments load via a separate lazy request when the popover opens — the main list query stays fast and the two fail independently.
Decided & shipped: Open on GitHub + Copy number / branch / URL — matches what already landed, no change needed. Checkout-in-pane and view-diff remain available as daemon-backed fast-follows.

05Behaviour & risks

  • Trigger: hover with ~350ms delay (no flicker while scanning), plus keyboard focus. The card link itself still opens GitHub on click.
  • Positioning: must portal to document.body with position: fixed — the stream is overflow-y: auto, so an absolutely-positioned popover would be clipped. Opens leftward, flips when near edges.
  • Coexistence: the existing checks-chip tooltip becomes redundant if the popover carries the full checks list — I'd remove it to avoid nested popovers.
  • Data: all "free" fields ride the existing single gh call by extending the shared fragment; adding body + latestReviews + labels grows the response for 90 nodes — worth a quick payload sanity check.
  • Risk: hover-only UIs are invisible on touch; the HUD is desktop-first so acceptable, but focus support keeps it keyboard-reachable.
  • Comments query: per review feedback, unresolved thread excerpts come from a dedicated /api/prs/threads endpoint fetched when the popover opens — never blocks or breaks the list.
