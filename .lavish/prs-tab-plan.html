How it works — mirrors the Linear integration

The daemon already shells out to gh (server/git-diff.ts calls gh pr view with timeouts, buffer caps, and a TTL cache), and the Linear panel already models "daemon-proxied third-party feed + 30s client polling" (server/linear.ts / linear-api.ts / src/LinearSection.tsx). The PRs tab copies that shape — no WebSocket protocol changes, no Swift changes (the AppKit app hosts the same web client).

Risks & edge cases

RiskHandling
gh unauthenticated / missing on the daemon hostThe API returns a typed auth_required error; the tab shows a one-line setup hint ("run gh auth login") instead of an empty list. Same graceful-degrade approach as the Linear panel with no account.
GitHub slow or rate-limitedTTL cache serves the last good payload with a "stale · synced 4m ago" footer; polling backs off on consecutive failures.
Huge repos (Save-All: 394 open)Fetch first 30 per state by last-updated; footer shows "30 of 394 · open on GitHub". No pagination UI in v1.
Closed/all viewsSame query with states:[CLOSED, MERGED] / no filter; fetched on demand, cached separately, never polled in the background.
SecretsThe daemon never stores a token — it always goes through your gh keyring auth. Nothing new lands in ~/.commando except repo names.

Build plan

  1. Worktree + server feed. server/prs.ts + server/prs-api.ts + unit tests (fake gh runner, cache TTL, error mapping). Register in server/index.ts.
  2. Client tab. hudTab strip in App.tsx below the (relocated) pinned note, PrsSection.tsx + CSS, polling hook, daemon-persisted repo prefs. Tests alongside the existing App tests.
  3. Extras + polish. Review-decision badge, conflict flag, needs-your-review group, tab attention dots, checks hover breakdown; empty/error/stale states; typecheck + vitest + drive it against the live daemon before merging.

Estimated at roughly a day of agent work end-to-end; ships as one reviewed branch per the repo workflow.
