What the daemon needs

Almost everything above reads from existing owner-authenticated surfaces. Four additions unlock the rest.

1 · Answer channel on /ws

Add answer_agent_request to ClientMessage and count owner sockets as interaction consumers. Today only the loopback companion socket can answer, so hooks are not even held open when Island is closed.

2 · Usage for owners

Broadcast ProviderUsage[] on /ws (or GET /api/usage). The service already exists; it only runs while a companion is connected.

3 · Push devices

POST /api/push/devices stores an Expo push token plus rules; the daemon posts to Expo's push API on status transitions. Quiet hours and mutes evaluate server-side.

4 · Pairing (optional)

A QR from the daemon that encodes host, port and a one-time code, exchanged for a device token. Avoids typing Tailscale IPs and keeps the owner password off the phone.
