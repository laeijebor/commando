Recommended system

Compact strip, adaptive detail drawer

Keep the current low-profile queue affordance, but make it a gateway to a durable editing surface. The drawer owns answer detail, per-answer notes, attachments, removal, Send this, and Send all.

  • Keyed controls rehydrate from the daemon snapshot after reload.
  • Local edits compare against the queued baseline and turn amber until re-queued.
  • The same optional note is editable beside the control and inside queue detail.
  • Images are uploaded separately and referenced by durable attachment metadata.
Why this direction

It scales in both dimensions. The collapsed strip preserves page context; the drawer supports batch triage without forcing narrow tiles to surrender permanent width.

Existing server support already sends selected IDs. Most of this is state synchronization and UI, not a queue rewrite.

State contract

Queued is a baseline, not a permanent checkmark

This live mock starts with Pro queued. Change the selection or note to see the control become dirty; “Update queued answer” establishes a new baseline. “Simulate reload” restores that queued baseline.

Which direction should settle the iOS fallback?

Matches queued answer
Rules
  • No pending item: blank/local draft, button says “Queue answer.”
  • Matches pending item: restored values, green “Queued ✓.”
  • Differs from pending item: current value remains selected, queued value gets a small baseline marker, status says “Changed since queued.”
  • Sent or removed elsewhere: reverse snapshot clears the queued baseline without erasing the current local draft.
Rehydration should be guaranteed for controls with a unique key. Unkeyed controls remain local-only; selector or prompt heuristics are too fragile to pretend otherwise.
