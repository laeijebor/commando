What the signal must do

Two states, readable across a wall of panes

The manual mark and post-mark activity should never collapse into one ambiguous “busy” color. The pane must retain the user’s intent while adding a second, unmistakable alarm.

Visible at a glance

Shape and placement do the work before labels become readable.

Preserve both facts

“Waiting for PR” remains visible when “new activity” is added.

Escalate meaningfully

Trigger on semantic agent milestones, not spinner churn or every byte.

More than color

Rail, label, motion, and count remain legible across themes.

State model

A mark is a durable intent, not a notification

Activity only changes the presentation. It never silently clears or replaces the user’s chosen status.

1Mark the pane

Context menu, command palette, or ⇧⌘M. Choose a named status and optional note.

2Persist with the pane

Show the same rail in the grid, session tree, maximized view, and after reload.

3Activity arrives

Meaningful agent milestone adds a cyan alarm, count, and timestamp without changing the mark.

4Acknowledge separately

Clear the activity alarm or open recent events. Keep, change, or remove the manual mark explicitly.

Recommendation

Use the rail as identity and the alarm as change

This is the only direction where the two facts remain visually independent at both pane scale and session-tree scale.

Recommended direction

Semantic rail + activity alarm

Keep the pane calm after marking, then deliberately break that calm only when something meaningful happens.

  • Named statuses: Waiting for PR, Ready to merge, Blocked, Release window, Parked.
  • Default trigger: semantic lifecycle or agent milestones; optional “any output” mode per mark.
  • Activity acknowledgement is separate from clearing or changing the manual mark.
  • Mirror the rail as a square marker in the session tree and as a count in the session row.
